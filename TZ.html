Техническое задание: универсальный интернет-магазин с админ-панелью и импортом из Excel

Версия 1.0 Дата: 26.10.2026 Хостинг: Beget (виртуальный хостинг) Исполнитель: Claude Code (облачная сессия)
Как читать этот документ исполнителю Каждое требование имеет идентификатор (например, SF-12, PR-04) и приоритет: MVP — обязательно в первой версии, Позже — не реализовывать сейчас, но не закрывать архитектурой. Порядок работ — в разделе 13, сквозные правила работы — в приложении C. При противоречиях приоритет: раздел 2 (ограничения хостинга) → раздел 3 (стек) → остальные разделы.

1. Общие сведения

1.1 Назначение

Универсальный интернет-магазин для продажи любых товаров. Владелец сам наполняет каталог: загружает категории и товары из Excel, управляет фотографиями, описаниями, ценами, главной страницей и тем, как покупатель приобретает товар — через корзину с оформлением заказа или через заявку на резервирование.

1.2 Цели

  • Запуск магазина без программиста: все настройки контента, цен и режимов продаж — в админ-панели.
  • Быстрое наполнение каталога: импорт тысяч товаров из Excel за минуты, повторный импорт обновляет данные по артикулу.
  • Минимальная стоимость владения: работа на самом дешёвом виртуальном хостинге Beget без VPS и платных дополнений.
  • Простая поддержка: стандартный стек, тесты, автоматический деплой из GitHub.

2. Ограничения среды: виртуальный хостинг Beget

Целевое размещение — самый дешёвый тариф виртуального хостинга Beget (Blog; при большом каталоге с фото — Start). Всё, что не работает на таком хостинге, не используется. Эти ограничения имеют наивысший приоритет.

ПараметрКак на BegetСледствие для проекта
Тип хостингаВиртуальный (shared), без rootНет демонов, Supervisor, Docker, WebSocket-серверов, Octane.
PHP8.3 (версия выбирается для сайта в панели; CLI: /usr/local/php/cgi/8.3/bin/php)Минимум PHP 8.3. Совместимость с 8.4/8.5 желательна.

Корень сайтаВеб-сервер отдаёт каталог public_html внутри каталога сайтаКорень Laravel = каталог сайта; public_html — симлинк на public.

  • Админка /admin (Filament)

  • Filament-ресурсы
  • Доменные сервисы (цены, режимы, остатки, заказы, импорт)
Хранилище
  • MySQL: каталог, обращения, настройки, очередь, кэш при необходимости
  • Диск: storage/app/public — фото
Фон (cron, раз в минуту)
  • schedule:run
  • → queue:work --stop-when-empty --max-time=50
  • Импорт, пересчёт цен, уведомления, снятие резервов
Внешние сервисы
  • SMTP (почта Beget)
  • Telegram Bot API
  • URL фотографий при импорте

Ключевые принципы

  • Бизнес-логика — в сервисах, а не в Filament-ресурсах и контроллерах: PriceCalculator, SalesModeResolver, StockService, OrderService, RowImporter. Это нужно для тестов и повторного использования (витрина, админка, импорт).
  • Итоговая цена денормализована в products.final_price и products.display_old_price — сортировка и фильтры по цене без вычислений в запросе.
  • Все длительные операции — пачками через очередь, с резервным запуском из браузера, если cron не настроен (6.10).
  • Изменение остатков — только через StockService в транзакции с блокировкой строки (lockForUpdate).
  • Цены в заказе фиксируются снимком (название, артикул, цена) — изменение товара не меняет старые заказы.
  • Деньги — DECIMAL(12,2), расчёты через целые копейки или bcmath, без float.

Определение действующего режима (SalesModeResolver)

  1. Если у товара включён «Цена по запросу» → inquiry.
  2. Если у товара задан режим (не «наследовать») → он.
  3. Иначе ближайшая по иерархии категория (сама категория товара, затем её родители) с заданным режимом.
  4. Иначе режим по умолчанию из настроек магазина.

Поправки на наличие (если учёт остатков включён)

  • Доступный остаток > 0 — режим работает как есть; количество в корзине/резерве ограничено доступным остатком.
  • Доступный остаток ≤ 0 и в настройках разрешено «Под заказ» — корзина работает, кнопка «Заказать (под заказ)», резерв недоступен.
  • Доступный остаток ≤ 0 и «Под заказ» запрещён — кнопки корзины и резерва неактивны с подписью «Нет в наличии», дополнительно доступна кнопка «Оставить заявку».

Действующий режим вычисляется одним сервисом и используется витриной, корзиной, оформлением и админкой (колонка «Режим» в таблице товаров показывает действующий режим и источник: товар/категория/магазин).

Алгоритм расчёта (PriceCalculator)

if product.fixed_price is not null:
    final = fixed_price
    old   = compare_at_price if compare_at_price > final else null
    return

price = base_price
rules = active rules matching product and current datetime

# Фаза 1 — наценки (markup_percent, markup_fixed, cost_markup_percent)
for rule in rules where phase = markup, order by priority desc, id asc:
    price = apply(rule, price)          # cost_markup_percent: price = cost_price * (1 + v/100)
    if rule.stop_processing: break
price_before_discounts = price

# Фаза 2 — скидки (discount_percent, discount_fixed)
for rule in rules where phase = discount, order by priority desc, id asc:
    price = apply(rule, price)
    if rule.stop_processing: break

price = max(price, 0)
if rounding applies (any rule applied, or setting "ко всем"):
    price = round(price, step, direction); if psychological and step >= 10: price -= 1

final = price
old   = max(compare_at_price, price_before_discounts if a "show as discount" rule applied)
old   = old if old > final else null

8. Фоновые задачи и планировщик

На Beget в панели «CronTab» создаются две задачи, обе — каждую минуту (пути — из docs/DEPLOY_BEGET.md):

* * * * *  /usr/local/php/cgi/8.3/bin/php /home/X/LOGIN/SITE/artisan schedule:run >> /dev/null 2>&1

14. Сценарии приёмки MVP

  1. Наполнение. Владелец загружает import-demo.xlsx с архивом фото → в каталоге товары в трёхуровневых категориях с фото и характеристиками. Повторная загрузка того же файла не создаёт дублей.
  2. Цены. Правило «Электроника +20 %» и акция «Смартфоны −10 %, показывать как скидку, до завтра» → на витрине верные итоговые цены, зачёркнутая старая цена и процент; в карточке товара в админке — объяснение расчёта. После окончания акции цена возвращается не позже чем через 15 минут.
  3. Режимы. Магазин по умолчанию — «Корзина», категория «Мебель» — «Резерв», один товар — «Цена по запросу» → в «Мебели» только кнопка «Зарезервировать», у товара по запросу — только «Оставить заявку», в остальных — «В корзину».
  4. Заказ. Покупатель кладёт два товара в корзину, выбирает доставку и оформляет → обращение в админке, остатки уменьшены, письмо покупателю и сообщение в Telegram отправлены.
  5. Резерв. Покупатель резервирует товар → доступный остаток уменьшился; без действий менеджера по истечении срока резерв получает статус «Истёк», остаток возвращается.
  6. Права. Менеджер обрабатывает обращения и товары, но не видит настроек и пользователей и не может удалить обращение.
  7. Внешний вид. Администратор меняет название, логотип, цвета и собирает главную из четырёх блоков → изменения сразу видны на витрине.
  8. Цикл Excel. Экспорт каталога → правка цен в Excel → импорт «Только цены и остатки» → цены обновились, записи в истории цен есть.
  9. Хостинг. Сайт развёрнут на Beget по DEPLOY_BEGET.md: HTTPS, страница «Система» без ошибок, предупреждения о cron нет, деплой из GitHub Actions проходит повторно без ручных действий.
  10. Качество. Lighthouse карточки товара соответствует NF-05, все тесты зелёные.

  • Одна валюта (₽), один склад, количество — целое число.
